# 按轮展示 Working events

2026-11-17 用户要求：持续对话只改变后端会话生命周期；前端继续使用旧 TAH 已确定的按轮展示，不将每条中途 agent message 都变成独立气泡。

- 每条用户请求对应一个 Alma 回答块。中途公开说明和工具事件归属于同一轮。
- 直接复用 `Working`：运行时展开最近三条公开过程和进度；完成后只保留完整日志入口。
- 最终/稳定回答仍在该轮的同一个回答块内呈现。明确标记为 commentary 的内容不会被当作最终回答。
- 直接复用 `WorkingLogPanel`、`WorkingEventRow`、Sheet 及原有日志跟随/手动滚动行为。
  新入口以“第 N 轮”替代旧 revision 标签，不引入 guardian/critic 或 revision 语义。
- 原生 SDK 的 phase、turn ID、公开事件顺序传到公共记录。创建新事件时保存时间；旧记录不虚构耗时。
- 重开会话时从原生 thread history 补齐已有消息的 phase；只更新元数据，不复制聊天消息。
- 聊天快照保留最近 100 条工具事件供轻量预览。完整日志按用户请求 ID 从宿主管理的 journal 读取，
  不依赖预览数组；每次至多保留 5,000 条工具事件，超限或正文截短时沿用日志面板的 limited 提示。
- 新工具详情每条最多保存 20,000 字符。旧版本已经截短的文字不凭空恢复；完整日志表示可用的落盘公开记录，
  不是原始私有推理或无限量工具输出。Agent 的私有 reasoning 仍不进入这个界面。

新增 `agent.workingLog({id})` 只接受当前 session 已存在的用户请求 ID；业务资产权限、模型/Skill 行为不变。
Agent 的执行顺序仍自主决定。此改动不增加业务调度器。

验收包含：跨轮归属、公开事件顺序、流式内容无重复、完成后的折叠行为、读取超过 100 条历史事件、冷重开，
以及复用旧组件的浏览器触摸布局。手机验证后为用户新建只有 transcript 的 workspace；不往这个新 workspace 写测试消息。

23 版真机结果：用户的 1 轮 ASR 审查被正确归为 1 个回答块（5 条 commentary、1 条 final_answer、40 条工具事件），原文和成果哈希不变。两轮只读任务验证运行中展示及重开后归属，另创建全新空白 workspace。一次调试状态读取超时已单独留记，实际推理正常完成，随后取样成功；没有将这次取样算作通过。
