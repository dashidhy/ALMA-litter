## 目标与基线

### 最新执行优先级（2026-11-01，用户再次明确）

当前P0是**正常核心流程完整移到手机并独立运行**：用户提供transcript、选择Structured Notes、
配置输出/交互语言、模型、推理强度和Web；执行Raw Guardian、Extra Guardian、多轮revision，
在手机本地验收、发布和查看历史。开发Mac只用于构建安装/观察，不参与业务调度或发布。

边界严格以Mac App为准：TAH Framework → Provider Adapter → Provider backend。先接Codex，
保留多Provider接口；没有已证实P0阻断不得改变或降低边界。优先复用原业务核心与合同，
平台接口和运行时适配须显式隔离。旧的Mac测试控制器不能作为手机实现。

异常恢复、完整故障矩阵和后台长任务评估后置；现有权限/凭证边界及正常任务清理仍须保留。
完成验收必须由手机界面发起，在同一个App生命周期连续完成多轮，不依赖Mac逐轮重启。

目标：先在手机上独立跑通与 Mac Alma Prototype 对齐的 TAH + Structured Note，覆盖
Raw Guardian、V0、V1、V2，以及联网纠错。本轮按用户最新指令优先验收正常前台主链路；
普通锁屏、后台长任务和异常恢复继续保留为后续重要验收项。
先单独完成 Agent，再接已定稿的 ASR、片段摘要、标题和前端。第一版 Provider 为 Codex，
复用用户订阅，不另建云服务器，不把用户引向另购模型 API。

- Codex 移植目标固定为 **0.166.0 / `6ff1e1ca…`**，这是 2026-10-31 已核验的稳定基线，
  不是声称在未来每次构建时仍为最新版本。用户本机 CLI 0.163.0 保持不变。
- Litter **2.1.9 / `366aefdd…`**，其原 Codex 基线为 0.155.1。
- iSH **`4f783cd9…`**；Python、Node、Bash 使用已验证的固定包清单。
- 默认 Agent shell 改为 Bash；明确选择其他解释器的内部脚本保留其语义。
- 权限目标是限制正常工具调用的访问范围。iOS App 沙盒承担 App 外部边界；ALMA 负责
  App 内部工作区、正式数据和凭证边界。**不宣称同进程解释器等价于独立 VM 的抗漏洞隔离。**

采用原 Mac AppActions/AuthService/Framework、原 Swift SQLite journal，显式移动平台接口，
保留 Framework → Provider Adapter → Provider backend 分层。Mac 只安装、启动和读取报告。

## 原问题、修法与验收标准（计划时状态；实际进度见上表）

档位沿用用户定义：High 为完整可行性仍不确定；Middle 为已有具体实施路径；Low 为
当前业务流程不用、可暂缓的能力。档位不表示影响轻重，也不表示是否已修好。

| 档位 / ID | 具体问题与当前证据 | 拟实施的修法 | 怎样才算通过 |
|---|---|---|---|
| **High · H2 后台长任务** | Litter 仅使用旧短时后台申请。Apple 新长任务 API 允许 CPU/网络继续执行，但模型/搜索等待期间可能没有真实进度，系统是否持续给运行时间尚未验证。 | 接 `BGContinuedProcessingTask`，由明确用户动作启动；报告真实阶段/工具进展，处理启动失败、排队、取消和到期。先用小型探针覆盖 CPU＋原生网络＋长等待，再接真实 Codex。不能用伪造进度、无声播放或反复短时续命代替。 | 无调试器的 Release 真机分别跑前台、切 App、锁屏。基础测试20–30分钟并加入15/45/120秒等待；最终以实际长 TAH 任务完成为准。记录停在哪里以及恢复方式；恢复完成不可冒充全程运行。若系统机制不匹配，保留 High 并报告具体证据。 |

## H1 隔离为何调整

截图中的 H1 是“完整保留 Mac 每次独立VM的硬隔离”，当时没有完整实施方案。后续已经将
手机方案具体化为：iOS提供App外部边界，ALMA控制guest挂载与原生文件访问，工作副本与
正式发布分离，工具网络与Provider网络分离。对应 **M10 + M3 + M12 + M2/M7**。

这是一条有明确改动位置的工程路线，因此按用户的可解决性标准拆入Middle。**调整不是
宣称隔离已证明成立，更不表示对任意解释器漏洞有VM等价保证。** 如果测试发现无法收敛
的宿主访问旁路或无法停止的跨任务副作用，应带证据重新升High，而不是扩大权限求通过。

## 目录和角色权限的具体约定

以下是逻辑视图，宿主真实路径由ALMA映射，模型不能选择任意宿主挂载源：

| 区域 | Raw Guardian / Guardian | Actor | 生命周期 |
|---|---|---|---|
| 工具基底（Bash/Python/Node及库） | 可读取/执行，不能修改 | 相同 | 固定版本共享；宿主负责安装和升级 |
| 本轮材料与旧revision的输入副本 | 只读 | 只读 | 从正式数据生成，结束后回收 |
| 本轮候选输出 | 若为本轮审查材料则只读 | 仅授权当前候选根可写 | 校验后由ALMA发布 |
| 本轮临时区与必要缓存 | 可读写 | 可读写 | 每attempt分开，不作为可信输入带入下一轮 |
| 正式录音库/数据库、其他任务目录 | 不暴露 | 不暴露 | 可信ALMA代码管理 |
| 凭证、控制器状态、发布元数据 | 不暴露 | 不暴露 | 可信运行时管理，不继承到guest |

“只读”不能只靠chmod：需核对写已有文件、删改目录、truncate、rename、链接及挂载权限。
`apply_patch` 使用官方解析器检查整份补丁，拒绝越界请求发生在写入前；原生文件访问层
在真正打开/写入时继续限制，不能用事后监控发现再杀进程代替。I/O故障仍可能产生部分
候选修改，因此正式数据发布另外做一致性保护，不假设多文件patch天然是原子事务。

## 实施顺序与停止条件

1. **固定输入和小型验证环境。** 复用已有工具包/真机测试壳，留存复现基线；补测试所需
   的Bash转发与UTF-8修复。独立探针不接整个App、不加载ASR/Gemma。
2. **尽早验证H2与文件边界。** 后台CPU/网络探针不依赖完整Codex升级，可先发现系统级
   阻断；挂载/原生文件访问先用临时哨兵目录验证，不接真实用户数据库。结果独立记录。
3. **完成0.166最小桥接及Middle必需项。** 保留文本TAH所需工具，补取消、权限、环境、
   文件视图和事件协议。所有修改以小模块与针对性回归推进。
4. **真实订阅与Web。** 登录入口准备好再由用户完成设备授权；先短任务核实原生Web与
   文件落盘。没有账号实测前，不把搜索/刷新标记为已通过。
5. **完整TAH与长任务对照。** 对相同材料跑Raw Guardian→V0→V1/V2，核对正式输出与
   允许差异；从短任务到NVIDIA长任务，分别覆盖前台、切App、锁屏、中断恢复并分阶段计时。
   模型输出不要求逐字一致，但必须符合相同任务/文件契约，关键纠错有可核对来源。
6. **最后接手机主流程。** Agent独立验收后才接ASR、自动摘要/标题、页面；再测组合内存、
   生命周期与后台行为，不能沿用小型探针的内存数作为整App预算。

如果H2的正常锁屏完成要求无法满足，先报告具体被收回执行权的条件，再讨论体验或个人Mac
方案；如果工具因权限无法完成合法任务，先查缺失能力与映射，不静默改成无限制执行。
本清单已获确认。运行代码修改与手机测试按上述顺序推进，不重复请求实施许可。
